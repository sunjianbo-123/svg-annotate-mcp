## 完整版(公众号 / 知乎 / README 顶部)

让 AI 改图,难的不是改,是说清楚改哪儿。"图例第二行右边那个字"这类描述,AI 只能猜,猜错就返工——位置信息经文字转述,必然有歧义。

另一个痛点是上下文。PPT / 设计类 AI 插件拿到的只是导出的一张图、一页幻灯:不知道图是哪个 matplotlib 脚本画的、数据在哪个文件、期刊模板有什么硬约束。改得再好也只是改产物,脚本一重跑就还原。

svg-annotate-mcp 用一个闭环解决这两件事:

🎯 **不描述,直接指。** 浏览器里打开 SVG 论文图,像网页设计工具一样悬停高亮、点选元素,配一句修改说明即成批注;也可以圈选区域、画箭头、写便签。

📦 **回传的是结构化锚点,不是截图。** 每条批注携带被点元素的语义 id(如 `text_54`)、逐字文字、层级路径与 viewBox 坐标,Claude 直接在生成脚本里 grep 定位,不靠猜。

🧠 **改在源头。** 它是接进 Claude Code 的 MCP 服务器——Claude 就在你的仓库里,读得到生成脚本、数据文件和论文模板约束。改脚本、重跑、页面秒级自动刷新,直接标下一轮,直到满意。

🔒 **本地、开源、零账号。** 批注服务只跑在 127.0.0.1,论文图不出你的机器。

改图的体验,从"给 AI 当翻译",变成"你指,它改"。

GitHub:<https://github.com/sunjianbo-123/svg-annotate-mcp>

## 短版(即刻 / 微博 / 朋友圈)

AI 改图两个痛点:位置说不清,靠文字描述来回猜;PPT 类 AI 插件没有项目上下文,改的只是导出产物,脚本一重跑就还原。

svg-annotate-mcp:浏览器里点选 SVG 元素、写一句说明,元素 id + 逐字文字 + 坐标实时回传 Claude Code——它就在你的仓库里,直接改生成脚本、重跑、页面自动刷新。你指,它改。
